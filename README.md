# 우리말답게 (urimal-dapge)

AI가 쓴 한국어를 우리말답게 고치는 Claude Code 윤문 스킬이에요. 번역투 표현과 리듬 같은 **어휘 티**뿐 아니라 **"누가 하는가"가 빠진 문장 뼈대**까지 점검해요.

> [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 `humanize-korean` 2.3.2를 바탕으로 만든 독립 파생판이에요. 원본의 진단 → 윤문 → 게이트 구조와 85개 패턴은 그대로 쓰고, 그 위에 구조 점검을 더했어요. 원작 라이선스는 MIT예요. 원본 문서는 [README.upstream.md](README.upstream.md)에 있어요.

## 왜 만들었나

원본 스킬로 업무 설계 설명문을 윤문했더니 변경률 1.6%로 모든 게이트를 통과했어요. 그런데 읽는 사람은 "여전히 이상하다"고 했어요. 문제 문장은 이런 것이었어요.

> 계약 통보서가 들어오면 시작한다.

어휘에는 번역투가 없어요. 문제는 두 가지였어요.

- **사물이 움직이는 주어:** 통보서가 스스로 들어와요. 한국어는 사람을 주어로 세우고 사물은 목적어로 내려요.
- **주어가 바뀌었는데 생략:** "(무엇이) 시작한다"의 주어가 비어 있어서 "통보서가 시작한다"로 읽혀요.

기존 룰북과 게이트는 어휘·리듬·의미 보존을 보기 때문에 이런 **행위자 구조**는 잡지 못해요.

> 업무는 마케팅 담당이 계약 통보서를 받으면서 시작된다.

## 원본과 다른 점

| 구분 | 내용 |
|---|---|
| **Phase 2.6 구조 점검** (신규) | 게이트 뒤 모든 경로(light 포함)에서 오케스트레이터가 직접 글을 독자처럼 읽으며 문장마다 "누가 하는가?"를 확인해요. LLM 추가 호출은 없어요. 행위자는 원문이나 작업 폴더(코드의 담당자 필드, 설계 문서)로 **확정될 때만** 채우고, 확정할 수 없으면 "행위자 확인 필요"로 표시만 해요. |
| **A-25** 사물 주어 + 행위·이동 동사 | "통보서가 들어오면", "수령 거부는 작업을 만든다" → 사람·부서·시스템을 주어로 |
| **A-26** 주어 전환 뒤 주어 생략 | 생략은 앞 문장과 주어가 같을 때만 해요. 바뀌면 주어를 써요. 원본 A-16(대명사)의 반대 방향 오류예요. |
| **C-15** 산문 속 메모체 기호 연쇄 | "초안 → 발송 → 도달 확인을 거쳐" → 동사 문장으로 |
| 자체검증 보강 | 윤문 중 주어를 지운 자리가 앞 주어와 같은지 확인해요(A-26 역주입 방지). |
| Windows Python 탐지 | `python3`이 Microsoft Store 바로가기에 걸려도 실제 인터프리터(`py -3`, `uv python find`)를 찾아 게이트를 건너뛰지 않아요. |

새 패턴 3개는 근거가 아직 문서 한 편이라 원본의 quick 예산 규칙에 따라 `quick: false`로 뒀어요. 대신 Phase 2.6이 모든 경로에서 이 패턴들을 점검해요.

## 근거

- **이근희(2008)**, 「번역투 관점에서 본 번역 텍스트의 품질 향상 방안」, 『번역학연구』 9(4)
  - 번역투 3,780건 중 무생물 주어는 2.7%였어요. 피동 관련 표현을 묶으면 2위(16%)예요.
  - "숨겨진 주체(행위자)는 사람이므로 … 능동으로"
  - 마지막에 독자처럼 읽으며 거르는 방법이 Phase 2.6의 근거예요.
- **2007 인지심리 실험**(『인지및생물심리학회지』 19(4)): 생략된 주어가 앞 문장 주어와 같을 때 이해가 빨랐고, 바뀌면 느렸어요.
- **박청희(2012)**: 주어 생략률은 한국어 약 68%, 영어 31.5%예요.
- **국립국어원 공공언어 지침(2013·2019)**: 짧게 끊기, 긴 명사 나열 피하기, 불필요한 피동 피하기를 권하고, '문장 성분 생략'을 오류 유형으로 분류해요.
- **LLM 연구:** "Lost in Literalism"(ACL 2025)에서는 프롬프트로 "자연스럽게"라고 요구해도 번역투가 안정적으로 줄지 않았어요. 그래서 사후 점검이 필요해요.

자세한 인용은 [`skills/humanize-korean/references/scholarship.md`](skills/humanize-korean/references/scholarship.md)의 "영형 주어와 주제 연속성"과 "LLM 출력의 영어 간섭" 절에 있어요.

## 설치 (Claude Code)

```
/plugin marketplace add sj-park-kr/urimal-dapge
/plugin install urimal-dapge@urimal-dapge
```

- 스킬 이름은 원본과 같은 `humanize-korean`이에요. "AI 티 없애줘", "사람이 쓴 것처럼 윤문" 같은 요청에 자동으로 동작하고, `/urimal-dapge:humanize-korean`으로 직접 부를 수도 있어요.
- 원본 `humanize-korean@im-not-ai`와 함께 설치하면 같은 이름의 스킬이 두 개가 돼요. **하나만 설치하세요.**
- 다른 설치 방식(스크립트, Codex, Copilot, Gemini)은 [INSTALL.md](INSTALL.md)를 보세요. 이 파생판에서 바뀐 부분은 Claude Code 경로에서만 확인했어요.
